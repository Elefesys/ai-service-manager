## M7.1A — поручение C1

**Результат для мастера.** В карточке конкретной работы мастер открывает согласованный сеанс, задаёт свою рабочую неделю и видит «Варианты времени». Исключение «Выходной» убирает все варианты на выбранную дату. Этим показом заканчивается M7.1A.

**База и ответственность.** Репозиторий `Elefesys/ai-service-manager`. Ветка `c1/m7-1a-session-availability` от проверенного `main` `ac30da7897cbf088cd8c9fb9262a52d67a278582`, цель PR — `main`. Начать с документационного коммита C0 в этой ветке. C1 ведёт один Draft PR и owner API, C2 отвечает за данные и чтение расписания, C5 подключает форму и предпросмотр к карточке. На базе единственная вершина Alembic — `0031`. C0 резервирует одну additive-миграцию `migrations/versions/0032_scheduling_availability.py` с `revision = "0032"`, `down_revision = "0031"`.

**Данные и поведение**

- Запрашивать варианты по явно выбранному сеансу. Сервер в контексте авторизованного владельца сверяет Workspace, Business, Client, Conversation, Request, принятую версию Quote, Order и Session. Минуты и их основание берутся из `QuoteMaterial.occupied_minutes` и `duration_reference_id`. Условия берутся из того же принятого Quote. При двух работах выбор в карточке задаёт конкретный сеанс. Права проверяются заново при каждом чтении и изменении настроек.
- Один основной ресурс на бизнес. Владелец явно активирует неизменяемую ревизию политики, относящуюся к этому бизнесу и услуге. Нужны IANA-зона бизнеса, недельные интервалы (в том числе с перерывом), замена часов или выходной на конкретную местную дату. Часы и исключения меняются через штатный owner API и экран. Применить буферы, сетку стартов, минимальное предупреждение и горизонт из явной тестовой политики. Предусмотренные планом сроки варианта и удержания пока являются параметрами политики. См. [Spec §§12.1–12.5](../architecture/01_ARCHITECTURE_SPEC.md#L2118), [ADR-082–085](../architecture/02_ARCHITECTURE_DECISIONS.md#L590) и [IMPL-007](../decisions/IMPL-007-m7-pilot-scheduling.md).
- Считать интервалы при чтении. В карточке показать название работы, длительность, локальную дату, зону, интервал визита и занятый интервал с внешними буферами. При отсутствии часов, активной политики или подтверждённой длительности показать владельцу причину пустого результата. ## Контракты последующих задач

**M7.1B — вариант, удержание, занятость.** Разделить расчёт вариантов (чтение), их выдачу (сохранение ограниченного списка со сроком) и реальный выбор. `AvailabilityOffer/option` связан с сеансом, областью клиента, ревизией политики и конкретными абсолютными интервалами. При выборе перечитать права/состояние, исходное согласие и длительность, рабочее окно, актуальность условий варианта и занятость; не принимать присланные произвольные timestamp/минуты или resource_id за основание. Выданный вариант не резервирует время. При изменении условий или конфликте дать новые варианты; не переносить на «похожее» время без клиента. В режиме переноса подбор учитывает только разрешённое собственное пересечение. Переносить/отменять может мастер по проверенному праву; клиентский запрос на изменение передавать мастеру, если нет явно принятого автоматического сценария.

Защитить в одной модели занятости физический интервал с буферами, а не только время, показанное клиенту. Для каждого ресурса предложения могут пересекаться, активные конкурентные Hold/Appointment/Block — нет. Предлагаемый путь: конечный `tstzrange`, границы `[start,end)`, положительная длина, DB exclusion для активных записей (равенство области ресурса + пересечение диапазонов); единственность активного обязательства для Session. Переход Hold→Appointment переводит одну занятость либо атомарно её заменяет, не оставляя окна для соперника. Создание/закрытие блока, изменение исключения на дату и захват/перенос участвуют в согласованном порядке блокировок. Область блокировки — ресурс, не весь Workspace. Соблюсти порядок уже существующих блокировок для config/контроля разговора при входе из worker. Чужие ID и причины блоков клиенту не раскрывать.

Удержание имеет неизменный срок и связь с опцией. На каждой конкурирующей команде после взятия блокировки прочитать доверенное время БД, убрать пересекающуюся истёкшую активную занятость, затем проверить/записать свою в той же транзакции. При чтении не предлагать занятое, истёкшее трактовать по тому же правилу. Индекс активной занятости опирается на явное состояние, не на `now()` в предикате. Не зависеть от системных часов браузера или регулярности фонового задания. Потеря ответа, вторая вкладка/новый AIRun и повтор доставки одного выбора не создают вторую бронь и не продлевают срок; тот же ключ с другим содержимым — конфликт. Явный новый выбор после истечения требует свежего варианта. Просроченный Hold не «оживает» по старому коду.

**M7.2A — два результата выбора.** Проверять snapshot предоплаты и длительности уже принятого Quote; завершившийся срок *предложения цены* не отменяет вовремя принятое соглашение. Отдельно проверить срок новой опции/удержания, актуальную авторизацию и ожидаемое состояние. При `NONE` явный выбор клиента достаточен для одного подтверждения, без лишнего сообщения «подтвердите ещё раз»; перевод удержания в Appointment и закрепление занятости атомарны. Если обработка выбора и конверсия — разные транзакции, после потери ответа возобновлять ту же операцию, не обещать запись до commit. Для остальных режимов Hold с `expires_at`, без Appointment, платёжной ссылки/чека и заглушек «оплачено». Ветка, не имеющая способа принять оплату, остаётся только тестовой; не предлагать её живым клиентам. Условия для M8: Hold ID, версия/статус, истечение, выбранный ресурс/интервал, Session/Order/Quote/terms/Client. Не создавать в M7 общедоступной команды «подтвердить платную бронь». Факт подтверждения/отмены и результат его доставки различимы.

**M7.2B — перенос и отмена.** Источник — ID/версия текущей записи + новый server option для того же Session. Старый интервал остаётся защищён до commit: в одной транзакции заменить только свою занятость, отметить старый Appointment CANCELLED, создать новый CONFIRMED с явной связью. Тот же интервал/тот же смысл — без новой версии записи на каждый повтор. Пример без буферов: 10:00–11:05 → 10:30–11:35 проходит, если мешает только прежняя запись; чужой блок 11:10–11:20 оставляет исходные 10:00–11:05 нетронутыми. При конфликте/исключении откатить все изменения и предложить заново выбрать окно. Отмена освобождает занятость один раз, сохраняет автора, время, причину и связь, оставляет исходный Order/Session доступным для решения мастера. Не снимать чужой Hold или сразу две разные работы одного клиента. Неразрешённый срок/политика отмены — решение мастера; никаких штрафов, автоматических возвратов или переноса платежей. Закрытие дня поверх защищённой записи/удержания сообщает конфликт мастеру, не стирает его и не показывает другому клиенту личные сведения.

**M7.3A — кабинет.** Достаточно дневного списка с переключением даты, местным временем/зоной и переходом к работе. Визуально различать «свободный вариант», «удержано до…», «записан», «истекло» и «отменено/перенесено». Источник текущего времени записи один и для карточки, и для календаря, включая исправление прежней надписи «без даты». После истечения или изменения другим оператором открытый экран должен обновиться адресным чтением; время сервера решает спор. Устаревшая версия команды — обновить экран, не применять к другой записи. Показать действия: исключение/блок, конфликт и кому из *своих* клиентов он относится, перенос, отмена, переход между старой и новой записью. Не нужен drag-and-drop, сетка нескольких сотрудников или конструктор графиков.

**M7.3B — из переписки.** Сначала доказать доменные команды. Новый закрытый тип намерения/адаптер использует тот же сервис, не расширяет задним числом [принятый v8](../../backend/src/asm/ai/contracts.py). Агент понимает пожелание «завтра после обеда», сервер разрешает дату в зоне бизнеса и возвращает несколько адресных вариантов. Клиент видит дату, время, зону, услугу и смысл выбора (бронь без предоплаты либо только Hold). Для пилота достаточно текстовой метки отдельной опции в отправленном списке, например «Выбираю S-…»; конкретную формулировку фиксирует C0. Это *не* код Quote M6; исходная реплика/доставленный список/диалог и разрешения проверяются сервером. «Первый» при двух актуальных списках, неясная работа или двусмысленная дата → один уточняющий вопрос, 0 удержаний. Изменённая/удалённая или чужая реплика, устаревшие права/Turn, takeover не исполняют новую AI-команду. Клиент не видит чужих записей. Не давать модели команду `create_appointment(datetime)`, произвольный SQL или права владельца.

После commit отправить правдивый результат через существующий Outbox, с защитой M3/M4/M6. Если место выиграл другой — сказать об этом и предложить новое; не считать отправку текста доказательством записи. При HUMAN/потере права на маршрут — актуальный статус мастеру, без нового автономного действия; уже исполненная бронь не пропадает, при UNKNOWN не отправлять автоматически повтор после рестарта. Детерминированное истечение и явно разрешённая ручная работа мастера продолжаются. Напоминания о визите, оплате и скором истечении — M9.

Для M8 передать ID и связи из обоих путей M7, сроки, версии, границу повторного вызова, результат гонки/истечения и одно читаемое доказательство для каждого. Денежный успех впоследствии не «воскресит» истекшее удержание: M8 сохраняет денежный факт, но заново проверяет право и занятость перед любым подтверждением. Для M9 остаётся доставка будущих напоминаний с проверкой актуальности. Оплату, фискализацию, синхронизацию календарей, запись нескольких мастеров/всего курса, лист ожидания и новые live-разрешения в M7 не выдавать.
