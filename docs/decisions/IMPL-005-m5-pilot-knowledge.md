# IMPL-005 — конфигурация, знания и изображения для пилота M5

Дата: 2026-11-12. Владелец решения: C0.
**Статус решения: PROPOSED; пакет планирования: REVIEW.** Реализация не начата.
Пользователь поручил подготовить весь M5 и явно исправить противоречия в пользу
работающего пилота. C0 принимает этот ограниченный scope перед первой выдачей;
до приёмки перечисленные ниже изменения не считаются отменой старых ADR.
План, зависимости и критерии: [M5_HANDOFF](../tasks/M5_HANDOFF.md).

## Зачем нужен этап

После M4 агент умеет вести защищённый текстовый разговор, но ещё не знает
подтверждённых услуг, правил и работ конкретного бизнеса. M5 должен дать
проверяемый результат: владелец публикует небольшой набор настроек и материалов;
AI отвечает по ним, разбирает доступное фото, находит подходящую работу и
собирает предварительное описание запроса для мастера. Неизвестное остаётся
неизвестным. Расчёт индивидуальной цены, согласование и запись принадлежат M6–M8.

## Минимальные контракты

### Истина и публикация

1. Подтверждённые структурированные правила выше объясняющего Knowledge; raw chats,
   Vision, извлечённые факты и похожие работы не устанавливают бизнесовые условия.
2. Draft не виден клиентскому runtime. Publish требует актуальную owner authority,
   deterministic validation, expected version и устойчивый повтор команды.
   Активный release переключается атомарно только на полностью готовый набор.
   Неудачный import/index/build сохраняет предыдущий активный release.
3. Формат включает только нужные сейчас service/intake/rule/style fields; цена,
   длительность и предоплата независимы. Неизвестное не заменяется нулём/прайсом
   fixtures. Калькулятор формул, Quote и PaymentRequest не создаются в M5.
4. Run закрепляет release/build/профили/версии использованных источников.
   Publish, rollback или отзыв материала меняет монотонную activation version.
   Новый read/result/send admission проверяет её; старый ещё не отправленный
   ответ не использует отозванные знания. Уже начатый внешний эффект нельзя
   обещать отозвать. Rollback создаёт новую активацию допустимого старого набора,
   не возвращает старый счётчик и не восстанавливает удалённые персональные данные.
5. Проверка актуальности и publication/send admission должны иметь согласованную
   точку сериализации, без DB locks через внешний HTTP. Не нужен event bus или
   массовое переписывание всех разговоров при каждой публикации.

### Знания и read tools

Runtime читает бизнес из доверенного контекста, не из model-supplied workspace ID.
Отдельные результаты для BUSINESS_KNOWLEDGE и PORTFOLIO; DurationCase — доступ
мастеру. Чужая история клиента не входит в общую базу бизнеса. Результат поиска
несёт источник/ревизию/authority, ограничен по размеру, не содержит storage keys,
credentials или скрытых полей. Пустой/противоречивый результат не даёт права
придумать правило. Инструкции внутри текстов/картинок не становятся system policy.

Сначала достаточно загрузить маленькую service card и релевантные знания сервером
в ContextPack. Новое read tool добавляется для конкретного полезного запроса;
не расширять tool budget/agent loop автоматически. Один обычный ответ сохраняет
ориентир 1 model call, при полезном read — до 2. Vision и embeddings учитываются
отдельно в общем конечном бюджете операции/TEST-сессии; не «бесплатно» вне ledger.

### Фото, портфолио и длительность

Анализируется только доступная текущая версия private media с серверным permit,
лимитами bytes/pixels/type и разрешённым data route. Не передавать модели S3
credentials/долгоживущий URL, не скачивать model-supplied URLs. Удалённый или
заменённый файл инвалидирует анализ и производные данные; прежнее
`MEDIA_REPLACED_UNAVAILABLE` остаётся видимым ограничением. Refetch заменённого
фото, если понадобится, требует отдельной задачи и не возникает как скрытый fix.

Vision возвращает наблюдаемые признаки и неизвестное; сантиметры без масштаба,
стоимость, длительность и медицинская пригодность не выводятся как факты.
Client reference, inspiration и MY_WORK различаются. Только подтверждённая
работа с разрешением показа становится клиентским Portfolio evidence.
Сходство не доказывает, что бизнес принимает такой заказ или выполнит его за
время/цену похожей работы. Исходящие изображения не получают public S3 доступ.

Owner ingestion нельзя строить на фиктивных Telegram сообщениях/клиентах ради
удобства старой схемы. Переиспользовать storage, validator, bounded HTTP и приёмы
учёта. Нужные отдельные upload/analysis capabilities добавлять узко. Для маленьких
наборов допустимы bounded операции concierge с durable outcome/receipt;
универсальная background AI platform и bulk pipeline не обязательны.

## Что остаётся OPEN до соответствующей задачи

- Точный разрешённый Vision и embedding route, modality, размер вектора,
  preprocessing, реальные usage/cost и лимиты. Text-only M4 approval это не закрывает.
  Проверить небольшой synthetic probe до основной реализации адаптера; без
  нового допуска на расход сначала fake/contract/local работа.
- Физическая схема и миграции, endpoints и read DTO для первого среза — C1/C2,
  далее ограниченные дополнения. Не фиксировать заранее число таблиц/маршрутов.
- Разрешённые данные настоящего мастера и включение реального бизнеса — перед
  live onboarding; его прайс/портфолио не являются условием начала разработки.

При тупике C0 фиксирует конкретный конфликт, минимальное изменение и последствия,
принимает техническое уточнение в пределах согласованного scope. Новая продуктовая
функция, утрата гарантии или paid/live действие выносятся пользователю явно.
Нельзя подменять реальную проверку PASS количеством тестов или изменением expected.
